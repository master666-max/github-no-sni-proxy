# github-no-sni-proxy

> 中国大陆网络环境下让 GitHub 恢复可用：**跑在本机 `127.0.0.1:443` 上的透明 TLS 反向代理**。

## 它凭什么能通

GFW 对 GitHub 的阻断**按 TLS 握手里的 SNI 字段精确匹配** —— 这解释了两件事：

- 换 IP、改 hosts、换 DNS 全都无效（阻断不认 IP）；
- **同一 IP、同一时刻，发 SNI 就超时，不发 SNI 就能拿到完整内容。**

所以思路很直接：浏览器照常访问 `https://github.com`，由 hosts 把域名指到本机，
反代完成 TLS 中间人，在**转发时不发送 SNI**，阻断就失效了。

与 FastGithub / Watt Toolkit 同源思路，区别是这里**纯 Python 标准库实现**：
不需要内核驱动，不改系统代理，不与其他代理软件争夺流量。

## 特性

- **零第三方依赖** —— 只用 Python 标准库，Python 3.11+ 直接跑
- **并发竞速选路** —— `4 个 IP × (正常 SNI / 无 SNI) × 2 轮`，谁先握手成功用谁
- **连接池复用** —— 避免每个请求都重吃一遍「握手成功但请求被吞」的十几秒
- **故障分级处理**
  - 通道级（体传输中断 / 刚建连接等不到响应头）→ 惩罚该 SNI 模式 180s，换另一条
  - 虚拟主机级（IP 真实但不属于该域名）→ 拉黑该 IP 600s
- **流式转发** —— 响应体不落内存，几百 MB 的仓库打包也不会撑爆
- **分帧严格按类型收尾** —— `chunked` 必须读到收尾块、`length` 必须读满、
  只有 `eof` 才是「上游关连接 = 正常结束」
- **白名单收口** —— 只有 GitHub 相关域名会转发，其余一律 403
- **内置自测** —— 147+ 项离线单测 + 真 `git push` 端到端，不联网约 12s 跑完

## 目录结构

```
gh-proxy.py      反代主体（唯一的网络核心）

undeploy.py      一键卸载：摘映射 → 删 CA → 删自启（可逆，带快照）
status_gui.py    状态监控窗口（纯 tkinter）
restart_proxy.py 重启逻辑（停旧起新）

selftest.py      离线自测（A 段单测 + C 段真 git push 端到端）

使用说明.txt      详细中文文档
```

## 快速开始

### 前置条件

- Windows 10 / 11
- Python 3.11 或更高（[下载](https://www.python.org/downloads/)，安装时勾选 *Add python.exe to PATH*）
- 管理员权限（写 hosts、监听 443、装根证书都需要）
- openssl（[Git for Windows](https://git-scm.com/download/win) 自带，装 Git 即可）

### 三步

**1. 生成证书**（每人必须自建，仓库内不含任何私钥）

```bat
python gen_certs.py
```

**2. 部署**

双击 `一键部署.bat`（会自动申请管理员权限）。
它会：备份 hosts → 把私有 CA 装进系统信任区 → 写入 36 条域名映射 → 启动反代。

**3. 验证**

双击 `状态监控.bat`，点「立即全链路测试」。
六行全部变绿 = 通了。

## 安全模型

| 项 | 做法 |
|---|---|
| CA 私钥 | **每人自建**，仓库永不包含 |
| 上游证书链 | 一律验证；「正常 SNI」模式连主机名一起核 |
| 「无 SNI」模式 | 没有主机名可核 → 用**根证书 SHA-256 钉扎**，链根不在白名单就拒 |
| 转发范围 | 域名白名单，非 GitHub 域名返回 403 |
| `alt-svc` 响应头 | 剥掉，否则浏览器记住 HTTP/3 地址后会绕过本代理 |

> ⚠️ 这是 TLS 中间人。**私有 CA 私钥等同于你所有 HTTPS 流量的伪造能力**，
> 请勿外泄，也不要把 `certs/*.key` 提交到任何仓库（`.gitignore` 已排除）。

## 它到底改了什么

只有三处，且都可逆：

1. **hosts 的标记块** —— 36 条 `127.0.0.1 <域名>`，夹在
   `# === gh-proxy BEGIN ===` / `# === gh-proxy END ===` 之间。
   卸载时只摘这一段，其余条目原样保留。
2. **系统 Root 存储里的私有 CA** —— 卸载时移除。
3. **`127.0.0.1:443` 监听** —— 关掉进程即释放。

**不改**：系统代理设置（`ProxyEnable` / `ProxyServer` 原样）、
不碰 v2rayN / Watt Toolkit / Clash 等其它代理软件、不注册常驻服务（除非你主动运行 `开机自启.bat`）。

## 日常操作

| 想做什么 | 双击 |
|---|---|
| 启动反代（前台，能看输出） | `启动反代.bat` |
| **改完代码后让它生效** | `重启反代.bat` |
| 体检 | `状态监控.bat` |
| 开机自动跑 | `开机自启.bat` |
| 恢复原样 | `一键卸载.bat` |

> ⚠️ **改完 `gh-proxy.py` 必须重启才生效** —— 反代是常驻进程，
> 加载的是它启动那一刻的代码。

## 自测

```bat
python selftest.py -A
```

`-A` 跑 A 段（离线单测）+ C 段（真 `git push` 端到端），**不联网**，约 12 秒。
改代码后建议先跑这个 —— 联机试验会被网络波动掩盖真正的 bug。

跑全量（含联网链路）：

```bat
python selftest.py
```

## 故障速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 浏览器报「连接被拒绝」 | hosts 还在拦截，但 443 没进程监听 | 双击 `启动反代.bat` |
| 反代在跑，但某些域名 502 | 链路抖动，或某个 SNI 模式被针对 | 等 3 分钟（模式惩罚自动过期），看监控窗口是哪条 |
| 面板显示「pid 文件过期」但端口在听 | 面板判活异常 | 新版已改用端口属主核对，不会再误报 |
| `重启反代.bat` 报「拒绝访问」 | 旧进程在更高完整性等级下运行 | 注销重登后再试 |

## 已知限制

- **只支持 Windows** —— hosts 路径、`certutil`、`schtasks` 都绑定了 Windows
- **只代理 GitHub 域名** —— 白名单机制，不做通用代理
- 不支持 WebSocket（收到 `Upgrade` 请求会按 RFC 剥掉 `Connection: Upgrade` 等头再转发）
- 反代进程本身不监听公网，仅 `127.0.0.1`
